## 一、核心结论

**无感切号 = 调用 IDE 宿主进程内部的私有 OAuth API，直接热替换运行时内存中的凭据，无需重启。**

关键 API 调用：

```typescript
// accountSwitchService.ts:275-279
await tokenApi.setOAuthTokenInfo({
  accessToken,
  refreshToken,
  expiryDateSeconds: Math.floor(expiryMs / 1000),
  tokenType: "Bearer",
  isGcpTos: false,
});
```

此调用完成后：

1. 宿主进程内存中的 OAuth 状态**立即更新**（当前会话生效）
2. 宿主内部**自动持久化**到本地存储（下次启动也保持新账号）
3. 无需重启 Antigravity

## 二、为什么需要桌面端 + 插件端协同

### 进程边界问题

Antigravity 是一个基于 Electron 的魔改 VS Code 应用。它的 OAuth Token 存储在 Electron 主进程的 V8 堆内存中，对外部进程而言是**不透明的黑盒**。

| 角色                        | 进程空间                             | 能做什么                           | 不能做什么                             |
| --------------------------- | ------------------------------------ | ---------------------------------- | -------------------------------------- |
| Cockpit Tools（桌面端）     | 独立的 Tauri 进程                    | 操作磁盘文件、管理多账号、监控配额 | ❌ 无法修改 Antigravity 进程的内存状态 |
| VS Code Extension（插件端） | 运行在 Antigravity Extension Host 内 | ✅ 调用宿主注入的内部 API          | 无法独立管理账号/配额                  |

**桌面端 = 大脑**（决策层：什么时候切、切到谁）
**插件端 = 手**（执行层：调用宿主 API 完成热替换）

### 两种切号模式对比

| 模式                     | 流程                               | 是否重启    | 使用场景               |
| ------------------------ | ---------------------------------- | ----------- | ---------------------- |
| **default（传统模式）**  | 关闭 Antigravity → 写入磁盘 → 重启 | ✅ 需要重启 | 插件不可用时的降级方案 |
| **seamless（无感模式）** | 桌面端写磁盘 + 插件端热替换内存    | ❌ 不重启   | 正常使用场景           |

## 五、WebSocket 通信协议

### 服务发现

桌面端启动时在 `ws://127.0.0.1:19528` 开启 WebSocket Server，并将端口信息写入共享配置文件：

```
~/.antigravity_cockpit/server.json
{
    "ws_port": 19528,
    "version": "x.x.x",
    "pid": 12345,
    "started_at": 1712649600
}
```

插件端启动时读取此文件获取端口，连接 WebSocket。

### 切号相关消息类型

| 方向            | 消息类型                          | 用途                        |
| --------------- | --------------------------------- | --------------------------- |
| 桌面端 → 插件端 | `event.plugin_switch_account`     | 下发切号指令                |
| 插件端 → 桌面端 | `response.plugin_switch_account`  | 回送切号结果                |
| 桌面端 → 插件端 | `event.account_switched`          | 广播切号完成（通知刷新 UI） |
| 桌面端 → 插件端 | `event.plugin_set_switch_mode`    | 远程设置切号模式            |
| 插件端 → 桌面端 | `response.plugin_set_switch_mode` | 回送模式设置结果            |
| 桌面端 → 插件端 | `event.data_changed`              | 通知数据变更（账号增删等）  |

## 六、宿主 API 详解

### API 发现机制

插件通过强制类型转换 `vscode` 全局对象，探测宿主注入的私有属性：

```typescript
// accountSwitchService.ts:359-385
private selectSeamlessApi(): SeamlessApiSelection {
    // 方式 1（优先）：新版统一接口
    const unified = (vscode as any).antigravityUnifiedStateSync?.OAuthPreferences;

    // 方式 2（备选）：旧版认证接口
    const legacy = (vscode as any).antigravityAuth;

    // 优先使用新版，两个都有也用新版
    if (unified && legacy) return { tokenApi: unified, apiName: 'OAuthPreferences' };
    if (unified)           return { tokenApi: unified, apiName: 'OAuthPreferences' };
    if (legacy)            return { tokenApi: legacy,  apiName: 'antigravityAuth' };
    return { tokenApi: null, apiName: 'none' }; // 不支持无感切号
}
```

### OAuthTokenInfoPayload 结构

```typescript
interface OAuthTokenInfoPayload {
  accessToken: string; // Google OAuth Access Token
  refreshToken: string; // Google OAuth Refresh Token
  expiryDateSeconds: number; // Access Token 过期时间（Unix 秒）
  tokenType: string; // 固定 "Bearer"
  isGcpTos: boolean; // 固定 false
}
```

### API 行为

调用 `setOAuthTokenInfo(tokenInfo)` 后，宿主进程内部：

1. **内存更新**：替换当前 OAuth 认证状态，后续所有 API 请求立即使用新 Token
2. **自动持久化**：宿主将新 Token 写入自己的本地存储（`state.vscdb` 或其他格式），确保重启后也保持新账号
3. **无信号广播**：不会触发 UI 刷新事件，需插件端主动通知

## 七、Phase 1 磁盘注入详解

### 注入目标

桌面端 Phase 1 写入的是 Antigravity 的 **user-data 目录**下的 `state.vscdb` 文件（SQLite 数据库）：

```
Windows: %APPDATA%\Antigravity\User\globalStorage\state.vscdb
macOS:   ~/Library/Application Support/Antigravity/User/globalStorage/state.vscdb
Linux:   ~/.config/Antigravity/User/globalStorage/state.vscdb
```

### 注入内容

```rust
// instance.rs:208-218
pub fn inject_account_to_profile(profile_dir: &Path, account_id: &str) -> Result<(), String> {
    let account = modules::load_account(account_id)?;
    let db_path = ensure_state_db_for_injection(profile_dir)?;
    // 直接通过 SQLite 写入 Token 到 state.vscdb
    modules::db::inject_token_to_path(
        &db_path,
        &account.token.access_token,
        &account.token.refresh_token,
        account.token.expiry_timestamp,
    )
}
```

### Phase 1 在无感模式下的作用

Phase 1 和 Phase 2 写入的是**同一份存储**（`state.vscdb`），但写入路径不同：

| 阶段    | 写入方式                               | 状态层                          |
| ------- | -------------------------------------- | ------------------------------- |
| Phase 1 | Cockpit Tools 直接用 SQLite 库操作文件 | 仅磁盘态（进程内存不知道）      |
| Phase 2 | 宿主 `setOAuthTokenInfo` 内部写入      | 内存态 + 磁盘态（宿主自动处理） |

因此在无感模式下，Phase 1 的磁盘注入实际上是**冗余的保底策略**：

- 如果 Phase 2 成功 → 宿主自动持久化，Phase 1 写入会被覆盖
- 如果 Phase 2 失败 → 至少磁盘态已是新账号，用户手动重启后可生效

## 八、自动切号触发流程

### 触发条件

```rust
// account.rs:1550-1630 (简化)
async fn run_auto_switch_if_needed_inner() {
    // 1. 检查自动切号开关
    if !config.auto_switch_enabled { return None; }

    // 2. 获取阈值（如页面截图中的 3%）
    let threshold = config.auto_switch_threshold; // 例如 3

    // 3. 判定当前账号是否触发阈值
    //    检查监控的模型分组中，是否有模型配额 ≤ threshold
    let trigger = evaluate_auto_switch_trigger(current, threshold, scope_mode, groups);

    // 4. 筛选候选账号（未禁用、配额 > 阈值）
    let candidates = accounts.filter(|a| a.quota > threshold && !a.disabled);

    // 5. 按配额从高到低排序，选择最优候选
    candidates.sort_by(|a, b| b.average_quota.cmp(&a.average_quota));
    let target = candidates[0];

    // 6. 执行双通道切号
    switch_account_dual_no_restart(&target.id, "auto", ...).await
}
```

### 配额刷新链路

```
定时器 (配额自动刷新间隔，如1分钟)
  → refresh_all_quotas_logic
    → 并发 5 个账号同时刷新
      → fetch_quota_with_retry (OAuth Token 刷新 + 配额 API 调用)
    → 刷新完成后触发 run_auto_switch_if_needed
      → 阈值判定 → 执行 switch_account_dual_no_restart
```

## 九、错误处理与降级

### 双通道错误处理 (account.rs:1964-2174)

```
switch_account_dual_no_restart
  │
  ├─ Phase 1 失败 → 直接返回错误，不执行 Phase 2
  │
  ├─ Phase 1 成功, 客户端未运行
  │   ├─ 尝试自动启动 Antigravity
  │   ├─ 启动失败 → 返回 "本地切换已完成，但客户端启动失败"
  │   └─ 启动成功 → 等待 12s 让插件建立 WebSocket 连接
  │
  ├─ Phase 2 成功 → 广播 account_switched + 记录历史（success=true）
  │
  ├─ Phase 2 失败（插件返回 success=false）
  │   → 广播 account_switched（磁盘已切好）
  │   → 返回 "本地切换已完成，但扩展无感切号失败"
  │
  └─ Phase 2 超时（12s 无响应）
      → 广播 account_switched
      → 返回 "等待扩展无感切号响应超时"
```

### 插件端错误码

| 错误码              | 含义                                     |
| ------------------- | ---------------------------------------- |
| `tools_offline`     | Cockpit Tools 未运行或 WebSocket 未连接  |
| `account_not_found` | 目标账号在本地凭据库中不存在             |
| `host_unavailable`  | 宿主不支持 `setOAuthTokenInfo` API       |
| `token_missing`     | 账号缺少 `accessToken` 或 `refreshToken` |
| `invalid_expiry`    | Token 过期时间无效                       |
| `switch_failed`     | Token 刷新失败或其他错误                 |

## 十、移植到其他 IDE 的指南

### 前提条件

1. **目标 IDE 基于 VS Code 架构**（Electron + Extension Host）
2. **IDE 宿主暴露了 OAuth Token 写入 API**（关键）
3. **IDE 支持安装自定义插件**

### 移植步骤

#### Step 1：API 探测

在目标 IDE 的插件中，探测宿主是否注入了 Token 管理 API：

```typescript
// 检查宿主是否暴露了可用的 Token API
function discoverTokenApi(): OAuthPreferencesApi | null {
  const api = vscode as any;

  // 尝试各种可能的 API 路径（不同 IDE 可能不同）
  const candidates = [
    api.antigravityUnifiedStateSync?.OAuthPreferences,
    api.antigravityAuth,
    api.windSurfAuth, // Windsurf 可能的 API
    api.cursorAuth, // Cursor 可能的 API
    // ... 其他 IDE
  ];

  for (const candidate of candidates) {
    if (candidate && typeof candidate.setOAuthTokenInfo === "function") {
      return candidate;
    }
  }
  return null;
}
```

#### Step 2：最小化桌面端

桌面端仅需实现：

- WebSocket Server（通信通道）
- 账号管理（Token 存储 + 刷新）
- 配额监控（定时轮询 + 阈值判定）
- 切号指令下发（`event.plugin_switch_account`）

**不需要**：磁盘注入 / 进程管理 / 实例管理

#### Step 3：最小化插件端

插件端仅需实现：

- WebSocket Client（连接桌面端）
- 监听 `pluginSwitchAccount` 事件
- 调用宿主 `setOAuthTokenInfo` API
- 回送结果

#### Step 4：Token 来源策略

有两种 Token 来源方案：

| 方案              | Token 来源                               | 优点               | 缺点                   |
| ----------------- | ---------------------------------------- | ------------------ | ---------------------- |
| A：桌面端统一管理 | 桌面端通过 WebSocket 下发 Token 给插件端 | 单一来源，一致性强 | 需要传输敏感凭据       |
| B：插件端自持凭据 | 插件本地凭据库（当前方案）               | Token 不过网络     | 需要独立的凭据同步机制 |

当前项目使用**方案 B**：插件端自己维护凭据库，桌面端只下发 `target_email`，不传 Token。

---

## 十一、安全注意事项

1. **WebSocket 仅监听 127.0.0.1**（本地回环），不暴露到网络
2. **Token 不通过 WebSocket 传输**（方案 B），桌面端只下发邮箱地址
3. **共享配置文件权限**：`~/.antigravity_cockpit/server.json` 仅本地可读
4. **心跳机制**：30s 间隔 ping/pong，检测连接存活
5. **请求超时**：12s 切号超时，防止无限等待

## 十二、术语表

| 术语                           | 解释                                                    |
| ------------------------------ | ------------------------------------------------------- |
| **无感切号 (Seamless Switch)** | 不重启 IDE 客户端，直接热替换 OAuth Token 实现账号切换  |
| **双通道 (Dual Channel)**      | Phase 1 磁盘注入 + Phase 2 内存热替换                   |
| **宿主 (Host)**                | Antigravity IDE 主进程（魔改 VS Code 的 Electron 进程） |
| **state.vscdb**                | VS Code/Antigravity 用于存储全局状态的 SQLite 数据库    |
| **user-data-dir**              | Antigravity 的用户数据目录（`%APPDATA%\Antigravity`）   |
| **Extension Host**             | VS Code 运行插件的隔离进程，与宿主共享部分 API          |
| **oneshot channel**            | Rust 端的一次性异步通道，用于等待插件响应               |
